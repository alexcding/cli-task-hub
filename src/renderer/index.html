Polling

TaskHub has no live connection to GitHub or Jira, so it checks on a timer instead. These are two independent fetch loops — GitHub PRs change far more often than Jira tickets, and each CLI hits a different rate-limited API — so they have their own intervals.

How often gh re-checks each project for PR/CI changes, new review requests, and merges. The GitHub API is rate-limited (5,000 requests/hour for an authenticated user), so polling too often across many projects can exhaust your quota. Lower = fresher data but more API calls. Minimum 15s.

How often acli re-runs your Jira queries. Tickets move slower than PRs, so this defaults higher. Minimum 30s.

JIRA Tickets

Used for ticket links. Leave blank to auto-detect from acli jira auth.

Only needed for writes acli can't do — e.g. setting a Fix Version on merge. Reads/transitions use your acli login. Generate one at id.atlassian.com → Security → API tokens. Stored locally.

Memory

Memory for open pages (GB)
How much memory the loaded pages may hold between them — PR and ticket pages as well as tabs you open. Over it, the least recently viewed are unloaded and reload where you left them when reselected. A page is measured, not counted: a heavy board and a small diff no longer cost the same.

Resource usage

Total RAM and CPU across every TaskHub process — the app windows, embedded GitHub/Jira views, the background server, and your terminals. Updates live.
